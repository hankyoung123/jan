# Phase 0-7 Evidence Audit

This audit maps each pre-Phase 8 requirement in
`docs/product-plan.md` to current repository evidence. A requirement remains
open when evidence is missing, indirect, or contradicted by retained upstream
artifacts.

## Result

- Phases 2-7 are complete against their written acceptance criteria.
- Phases 0 and 1 remain partial because repository ownership, the AGPL
  distribution decision, cross-platform packaged launch evidence, and
  remaining release branding are not complete.
- The local canonical-storage and minimum-window gaps previously recorded for
  Phases 0 and 1 are now covered by executable CI gates.

Verification snapshot on 2026-08-01:

- Core/Web/extensions: 290 files and 3,274 tests passed.
- Python Story Engine: 108 tests passed.
- Story-owned Tauri runtime: 7 focused tests passed.
- Playwright: all nine primary routes passed at `1024x740`.
- Web lint/build, Ruff, mypy, Python package build, OpenAPI drift, and generated
  TypeScript contract checks passed.

Follow-up verification on 2026-08-01:

- Python Story Engine: 119 tests passed.
- Story product boundary, branding, distribution, licensing, and packaging
  regression tests: 30 tests passed, including the updater security boundary
  and CLI branding boundary.
- Tauri desktop library and `story-engine-cli`: `cargo check --features cli`
  passed.
- `git diff --check` passed.
- Active updater/download Rust sources no longer contain the inherited
  `JAN_SIGNING_KEY` name or a hard-coded development secret; optional HMAC
  signing now uses `STORY_ENGINE_UPDATE_SIGNING_KEY` and fails closed when it
  is absent. `productSecurityBoundary.test.ts` covers this boundary.
- FastAPI/Tauri model bridge failure messages and Concordia adapter validation
  errors no longer expose Jan or Concordia implementation names to the UI;
  model-route, project-route, and adapter tests assert Story Engine language.
- Active Story Engine UI copy no longer exposes the inherited `Jan-Code`, `Jan
  Browser MCP`, or `What is Jan?` product labels, including the previously
  missed Polish and Czech browser-extension descriptions; compatibility server
  keys, provider IDs, and model infrastructure identifiers remain intentionally
  unchanged. `productBranding.test.ts`, `ThreadList.test.tsx`, and the browser
  MCP hook tests cover this boundary.
- Browser MCP now stores a separate `displayName`; its settings card, status
  messages, confirmations, and dialog titles show `Browser MCP` while the
  legacy runtime key remains stable for existing configurations.
- Post-change full regression on 2026-08-01: `yarn test:jan` passed (Core
  152, Web 2913, retained extensions 235), `yarn test:story` passed (119),
  `yarn lint` passed, `yarn typecheck:story` passed, and the MCP settings
  route rendered in a local browser with `Browser MCP` visible, no inherited
  label, and no document/body overflow.
- The inherited Windows NSIS migration template is now outside the active
  `src-tauri` packaging directory under `docs/upstream/jan/workflows-packaging/`;
  `tauri.windows.conf.json` does not reference a custom NSIS template, and the
  packaging/distribution tests guard both facts.
- The package default binary is now cfg-gated when the `cli` feature is
  enabled, so the documented `cargo check --features cli` command compiles the
  desktop library and CLI configuration consistently.
- CI-equivalent desktop gates were rerun locally: whole-desktop Clippy with
  `-D warnings` passed, and `yarn tauri build --no-bundle --
  --no-default-features --features test-tauri` produced the release desktop
  binary successfully. Only the pre-existing retained llama.cpp dead-code
  warning and Vite chunk-size advisories remain.
